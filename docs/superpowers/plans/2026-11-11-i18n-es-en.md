# Spanish / English UI (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every UI text and user-facing message follows the user's saved language (`es` or `en`); Spanish is the default.

**Architecture:** Angular build-time i18n. One build makes two copies, `/en/` and `/es/`, from English source text plus `src/locale/messages.es.json`. nginx sends un-prefixed URLs to `/es/...`. After login, a user whose saved language differs from the copy they are on is sent to the other copy; Preferences does the same after saving.

**Tech Stack:** Angular 22 (`@angular/localize` already installed, polyfill `@angular/localize/init` already set), Vitest via `ng test`, nginx image tests (`node --test`), Postgres bootstrap script.

**Spec:** `docs/superpowers/specs/2026-11-11-i18n-es-en-design.md`

## Global Constraints

- **No feature flag** for this work (owner's decision; overrides the `CLAUDE.md` flag rule here).
- Spanish addresses the user as **"tú"**; records vocabulary follows the Spanish terms of **ISO 15489**. Claude writes all the Spanish; the owner reviews it in the PR.
- English is the source text. Languages: `en`, `es` only. New users `es`; existing users keep their value.
- Server error text and logs are not translated (the frontend shows its own messages).
- `CLAUDE.md` rules: TDD (failing test first), zero `any`, `knip` clean, `prettier --check .` and `ng lint` pass, AXE/WCAG AA, conventional commits.
- Jira ticket **SCRUM-32**; branch `feature/scrum-32-i18n`; commits and the PR mention `(SCRUM-32)`. Do not merge; the owner says "merge".
- **Route names are not translated** (owner's decision): `/users`, `/upload`, `/login` stay English in both copies; only the language prefix is added (`/es/users`, `/en/users`). Never put `i18n` on route paths.

## Review Focus

1. A logged-in `en` user opening `/es/users/abc/edit?x=1#y` lands on `/en/users/abc/edit?x=1#y` (path, query and hash kept). Task 1.
2. Old bookmarks without a prefix (`/users`, `/login`) still work: they redirect to `/es/users`, `/es/login`. Task 5.
3. `ng serve` (no prefix in the base href) never redirects, so no reload loop in dev or in unit tests. Task 1.
4. No redirect loop: saved language equals the copy means no navigation; a refused save neither changes the language nor navigates. Tasks 1 and 2.
5. `/config.json` is requested relative to the base href, so `/es/config.json` and `/en/config.json` must return the same no-store JSON. Task 5.

### Task 1: Locale helpers and service

**Files:**
- Create: `frontend/src/app/i18n/locale.ts`, `frontend/src/app/i18n/locale.service.ts`
- Test: `frontend/src/app/i18n/locale.spec.ts`, `frontend/src/app/i18n/locale.service.spec.ts`

**Interfaces:**
- Produces:
  - `languageOf(localeId: string): Language` (`'es'` for `es` and `es-*`, otherwise `'en'`).
  - `localizedUrl(language: Language, location: { pathname: string; search: string; hash: string }): string`: replaces a leading `/en` or `/es` segment of `pathname` with `/<language>`, keeps search and hash.
  - `NAVIGATE: InjectionToken<(url: string) => void>`, default `(url) => window.location.assign(url)`.
  - `@Service() LocaleService` with `readonly current: Language` (from `LOCALE_ID`), `isLocalized(): boolean` (true only when the document base href is `/en/` or `/es/`), `redirectIfNeeded(language: Language): void`, `switchTo(language: Language): void`. Both navigate through `NAVIGATE` and only when `isLocalized()` and the language differs from `current`.
- Consumes: `Language` from `auth/auth.service.ts`.

- [ ] **Step 1: Write the failing tests.** `locale.spec.ts`: `languageOf('es')`, `languageOf('es-BO')` are `'es'`; `languageOf('en-US')`, `languageOf('en')` are `'en'`; `localizedUrl('en', { pathname: '/es/users/abc/edit', search: '?x=1', hash: '#y' })` equals `/en/users/abc/edit?x=1#y`; `localizedUrl('es', { pathname: '/en', search: '', hash: '' })` equals `/es`. `locale.service.spec.ts` (override `LOCALE_ID` and `NAVIGATE`; set the base href with a `<base>` element in the test document): with base `/es/` and `current` `es`, `redirectIfNeeded('en')` calls `NAVIGATE` once with the localized URL, `redirectIfNeeded('es')` does not; with base `/` (dev), `redirectIfNeeded('en')` never navigates; `switchTo` behaves like `redirectIfNeeded`.
- [ ] **Step 2: Run** `cd frontend && npx ng test --watch=false` and confirm the new specs fail (modules missing).
- [ ] **Step 3: Implement** the interfaces above. `isLocalized()` reads `inject(PlatformLocation).getBaseHrefFromDOM()` and matches `/^\/(en|es)\/$/`.
- [ ] **Step 4: Run** the same command; all pass.
