# Blueprint update: design

Date: 2026-11-17. Status: approved by the owner in chat ("go"). Written by Claude; the owner's decisions are marked.

## Why

`blueprint/` creates a new monorepo "configured like this project", but it was last changed on 2026-11-04 and the app is
193 commits ahead. A new project today gets none of: the API response envelope, `parseBody`, the database module, login,
refresh tokens, users, the runtime `config.json`, en/es i18n, the Docker images with nginx and CSP, the GitHub workflows,
Terraform, or the newer conventions (`.html` templates over 5 lines, `.model.ts` files, flags only for incomplete work).
The README already warns that `templates/` are copies that drift. This work updates the blueprint **and** stops it
drifting again.

## Decisions (owner)

- **Scope:** foundation + login and users (not clients, uploads, documents, Tika, Pub/Sub).
- **Infrastructure:** include Terraform too, parameterized (project id, region, names), plus the Dockerfiles and the
  GitHub workflows.

## Decisions (Claude's calls, to be checked)

- **Templates are generated from the live app, not hand-copied.** A script, `blueprint/sync-templates.mjs`, holds a
  manifest of app files (or folders) to copy into `blueprint/templates/` with placeholder replacements. Updating the
  blueprint means running it. `--check` exits 1 when a template differs from what the sync would write, so it can run
  in CI or before a PR.
- **Two kinds of template files.** *Synced* files are verbatim copies of the app's with placeholders. *Composed* files
  differ on purpose because the blueprint has fewer features (`app.module.ts`, `env.validation.ts`, `.env.example`,
  `db-bootstrap.mjs`, the routes, the side menu, `README`, `CLAUDE.md`); they stay hand-written in `templates/`, but are
  rebuilt from the app's current version when this work runs.
- **Placeholders** (existing: `__PROJECT_NAME__`, `__PROJECT_TITLE__`, `__DB_NAME__`; new): `__PREFIX__` (Angular selector
  prefix, `dms` in the app), `__GCP_PROJECT__`, `__REGION__`. Any other project-specific string found in a synced file
  is made a placeholder or the file becomes composed.
- **No Nexo logo or favicon in the blueprint:** a neutral text title and the default favicon; the owner's artwork is not
  reusable by other projects.
- **Verification** (the end of the work): run `create-project.mjs` into a temporary folder and run the new project's
  build, lint and unit tests; a CI-free check, done by hand and reported.

## Out of scope

Clients, uploads, documents, the Tika worker, Pub/Sub, dead-letter handling, the Nexo artwork, a published npm package for
the script, pinning dependency versions (the README's existing rule stays: latest versions).

## Phases (each ends with a commit; one PR when the owner says so)

1. **Sync tool + backend foundation:** `sync-templates.mjs` (manifest, placeholders, `--check`, tests); backend `common/`
   (envelope, `parseBody`, filters, interceptor), `database/`, `logging/`, `app.setup`, `swagger.setup`, health with the
   database check, `scripts/pull-env`, the backend Dockerfile.
2. **Backend login and users:** `auth/`, `users/`, models, `users-create`, `admin-connection`, `db-bootstrap` (users and
   refresh_tokens only), their env variables.
3. **Frontend:** runtime config, API interceptor, auth (service, guard, interceptor, login), en/es i18n (`angular.json`
   patches by the script), shell (toolbar, side menu, theme), users screens, `pull-config`, nginx image with CSP.
4. **Infrastructure and CI:** Terraform and the workflows, parameterized.
5. **Docs and verification:** `CLAUDE.md` rules, README, then a throwaway project built end to end.

## Risks

- `angular.json` is generated by the Angular CLI; patching it for i18n must tolerate CLI changes (fail loudly if the
  shape is not what the script expects).
- Terraform has many project-specific names (44 mentions of dms/doc-management/nexo): the first parameterization pass will
  need review by the owner.
- `ng new` and `nest new` output changes between CLI versions, so composed files can clash with new scaffolds.
